# The form of a rule

A rule fails in a particular way, and the form that repairs it follows from
that way and not from taste. The rows below come from measured head-to-head
wording tests (obra/superpowers, `skills/writing-skills/SKILL.md`, "Match the
Form to the Failure"), so a row changes when a new measurement says so.

Find the failure your rule prevents, then write it in the form that column
names.

| Failure class | Form that works | Form that fails | Why |
| --- | --- | --- | --- |
| A rule skipped under pressure | A prohibition that carries its price and quotes, verbatim, the rationalisation it counters | An unpriced reminder to keep the rule in mind | Under pressure an agent trades away a rule whose cost of skipping is unnamed, and an unquoted excuse stays available. |
| A wrong output shape | A recipe that states what the output is | A list of prohibitions | A ban names what not to emit and leaves the shape unstated, which measured worse than no guidance at all. |
| An omitted required element | A required slot in the schema or the template | Prose in the body asking for the element | A slot makes the omission visible in the artefact, while prose is satisfied by an agent that believes it complied. |
| Behaviour that depends on a condition | A rule keyed to an observable predicate | A judgement call, or an exemption bolted onto the general rule | A predicate the agent can evaluate decides both branches, and a judgement call decides neither. |

Never patch a working rule with an exemption clause. Re-cut the rule on an
observable predicate instead, and state each branch on its own: one appended
exemption measured a working rule down from consistent to noisy.

## The form of a description

A description names the occasion to reach for the thing it fronts — the
situation that calls for it, and what it hands back — and never walks through
the steps inside it. A description that summarises a workflow becomes the
shortcut agents take instead of reading the body: one measured case ran a
single review where the body ordered two, because the description said "review
between tasks".

This page stays in this checkout rather than in the shipped brief because it
binds whoever writes a page here, not an agent at run time.
